# Neural Amplifier v0.3.3

This patch adds a `[seats]` configuration table and a brain that routes each
decision to the seat that owns its faction, and fixes headless launches of game
copies configured for a large window.

## Changes

- **`[seats]` in `na.toml`.** Each `[seats.<faction_id>]` table (ids 1 to 7)
  names who plays that faction: an accountable principal, the reflex that answers
  each decision, and an optional strategist, model and budget. The table is
  validated strictly at load. An unknown key, an out-of-range or duplicate
  faction id, or a reflex that is not built yet is a configuration error, not a
  silent default. `python -m neural_amplifier.config llm-factions` prints the
  `llm_factions` bitmask the seats imply, and prints nothing when there is no
  `[seats]` table.
- **Seat routing.** With a `[seats]` table, the service builds a `seats` brain
  that sends each decision to the driver of the seat that owns its faction:
  `scripted`, `claude`, `claude-code` or `agent`, built with the same
  constructors as before. The faction comes from the engine-reported
  `faction_id`, now a typed optional field on the world view rather than an
  untyped extra. A decision for an unseated faction, or one with no
  `faction_id`, is not routed: it degrades to the deterministic tier like any
  other brain failure. Decision records gain `seat` and `seat_principal`.
  Without a `[seats]` table the brain is built exactly as in v0.3.2.
- **`scripts/play-thinker.sh` derives `llm_factions` from `[seats]`.** When
  `thinker.ini` has no `llm_factions` line, the script writes the derived value.
  When `thinker.ini` already sets a different value, the script stops and says
  which two sources disagree, rather than guessing. Without a `[seats]` table,
  behaviour is unchanged.
- **Headless Xvfb screen sized from the game window.** The headless launcher
  used a fixed 1280x1024 virtual screen. A game copy whose `thinker.ini` sets a
  larger `window_width`/`window_height` (for example 2560x1440, from an attended
  install) then failed at `X_CreateWindow` with `BadWindow` before the main menu.
  The screen now follows `thinker.ini`, falling back to 1280x1024, and
  `NA_XVFB_SCREEN=WxHxD` overrides it.
- **Documentation.** Seat and per-faction policy design, a skill-library design,
  notes on upstream Thinker v5.6 steerability, adapter citations re-verified
  against the Thinker fork's v5.6 sync, and corrected README status and coverage
  figures.

The two `scripts/play-thinker.sh` changes ship in the repository source, not in
the wheel or source distribution, which contain only the Python orchestrator.

## Not tested for this release

- No game was launched for this release. The `BadWindow` failure was observed
  on one host; this release does not record a headless launch that reaches the
  main menu with the fix, at any resolution or with `NA_XVFB_SCREEN` set.
- The `[seats]` loader and `llm-factions` command are covered by unit tests. The
  `play-thinker.sh` paths that write or refuse `llm_factions` were not run end to
  end against a real `thinker.ini`.
- Seat routing is covered by unit tests with scripted drivers only. No game was
  played with two or more seats, and no decision from a real engine was routed
  through the `seats` brain.
- Seat tokens and per-seat decision logs are not in this release. Four
  agent-facing tools still take a caller-supplied `faction_id`, and any agent
  can claim any queued decision, so seats are not yet isolated from one
  another.
- No model calls were made. The seat fields `strategist`, `model` and
  `budget_usd` are parsed and validated, but nothing in this release acts on
  them yet.
- The published wheel was not installed into a game environment.

The release provides the platform-neutral Python orchestrator as a wheel and
source distribution, with checksums. Game adapters and copyrighted game assets
are not bundled. Neural Amplifier remains pre-alpha.
